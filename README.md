# QA Deck

QA Deck: локальна плагінна платформа для підготовки, перевірки, перемикання та
відновлення стану QA-середовища навколо тестованого Product. Product представляє
програму або систему, з якою працює QA-інженер.

QA Deck допомагає бачити й відтворювати стан середовища, потрібний для перевірки
Product. Це не test runner для запуску тестів інших програм. Проєкт перебуває в
активній розробці.

## Що вже працює

- створення і локальне збереження Products із параметрами executable, робочим
  каталогом та аргументами запуску;
- Flask web UI, адаптивне оформлення і health endpoint `/health`;
- Plugin API, Plugin Manager, виявлення вбудованих плагінів і окрема
  конфігурація плагінів для кожного Product;
- Executable Inspector із перевіркою шляху та основних метаданих без змін;
- License Manager із перевіркою стану, попереднім планом, резервною копією,
  приховуванням і відновленням налаштованих ліцензійних файлів;
- Log Collector із перевіркою джерел і формуванням ZIP-архіву;
- Windows Registry із values і branches, налаштованими для конкретного Product,
  presets,
  попереднім переглядом і підтверджуваним виконанням;
- Snapshot capture, Snapshot Diff, порівняння з Current, порівняння snapshots,
  контрольоване видалення та підтримуваний Snapshot Restore;
- Environment Profiles для окремих Products із бажаним станом Registry і License
  Manager, автоматичним порівнянням та підтверджуваним застосуванням;
- локальний Operation Log для виконаних операцій;
- автоматизована перевірка проєкту за допомогою pytest і Ruff.

Windows Registry працює тільки з явно налаштованими ресурсами конкретного
Product. Підтримуються values і окремі branches, а presets показують перехід від
поточного до бажаного стану. Values можна застосовувати після попереднього
перегляду. Branch приховується або відновлюється через перейменування, без
видалення і повторного створення. Перед виконанням стан перевіряється ще раз.

Snapshot зберігає фактичний стан середовища Product у певний момент. Snapshot
Diff показує changed, added, removed та unchanged resources для порівняння
Snapshot із Current або двох snapshots. Snapshot Restore має окремий попередній
перегляд і автоматично відновлює лише підтримувані ресурси, які можна безпечно
зіставити з поточною конфігурацією. QA Deck не виконує довільний відкат усього
Windows-середовища.

## Snapshot і Environment Profile

Snapshot відповідає на питання, що було фактично зафіксовано в певний момент.
Environment Profile описує, яким має бути середовище. Це різні способи роботи зі
станом, а не взаємозамінні копії одних даних.

Environment Profile належить конкретному Product і може поєднувати бажаний стан
кількох плагінів. Зараз у ньому беруть участь Windows Registry і License
Manager. Profile автоматично порівнюється з Current, має попередній перегляд та
окреме підтвердження застосування. Поточна конфігурація Product визначає, куди
дозволено виконувати зміни.

## Плагінна архітектура

QA Deck має плагінну архітектуру. Ядро координує спільні сценарії, але
не повинно знати деталі роботи конкретного Windows Registry або License Manager.
Плагіни можуть додатково підтримувати Snapshot чи Environment Profile, якщо це
потрібно. Помилка одного плагіна по можливості ізолюється від незалежних
плагінів. Детальніший контекст наведено в
[описі проєкту](docs/PROJECT_CONTEXT.md) та
[архітектурних рішеннях](docs/DECISIONS.md).

## Як виконуються зміни

- перед підтримуваною зміною користувач бачить попередній перегляд;
- для виконання потрібне явне підтвердження;
- перед записом QA Deck повторно перевіряє поточний стан;
- поточна конфігурація Product визначає дозволені ресурси;
- старі шляхи зі snapshots не використовуються як довільні адреси для запису;
- Registry обмежений налаштованими targets, а License Manager використовує
  резервну копію і захист від перезапису кінцевого файла.

Ці перевірки зменшують ризик небажаних змін, але не замінюють контрольоване
тестове середовище та перевірку плану користувачем.

## Локальне збереження

Products, конфігурації плагінів, snapshots, Environment Profiles та Operation
Logs зберігаються локально у JSON-файлах усередині Flask instance directory.
Ці файли не додаються до Git.

## Поточні обмеження

- Workflow / Setup ще не реалізований;
- Jira Integration ще не реалізована;
- запуск executable із QA Deck ще не реалізований;
- глобальної транзакції між кількома плагінами немає, тому можливий частково
  успішний результат;
- дані підтвердження і результати Snapshot/Profile execution зараз зберігаються
  в пам'яті процесу та втрачаються після перезапуску;
- UI ще потребує точкових доопрацювань.

## Встановлення

Потрібен Python 3.11 або новіший. Коротка установка для Windows PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
```

## Запуск

```powershell
python run.py
```

За замовчуванням застосунок буде доступний за адресою
`http://127.0.0.1:5000/`.

## Перевірка

```powershell
python -m pytest -q
python -m ruff check .
```

Повний накопичений набір автоматизованих тестів проєкту на поточному етапі
містить 191 тест. pytest перевіряє сам QA Deck, а не тести інших програм.

## Наступний етап

Основний наступний напрям: Workflow / Setup з однією простою послідовністю
Plugin Actions, попереднім переглядом і результатом виконання. Також заплановані
точкові UX-покращення, стабілізація і продовження документації. Jira Integration
залишається пізнішим напрямом. Деталі наведено в
[дорожній карті](docs/ROADMAP.md).
