# Дорожня карта QA Deck

Це робочий план дипломного проєкту. Пункти наступних тижнів описують заплановану роботу й не означають, що ці функції вже реалізовані. Фактично виконані результати позначено окремо. План може уточнюватися в міру розробки.

## Тиждень 1 — Базовий застосунок

Фактично виконано:

- створено структуру Python-проєкту із `src-layout`;
- додано Flask application factory і `Blueprint`;
- реалізовано модель `Product`;
- додано локальне JSON-сховище;
- реалізовано створення продукту через вебформу;
- додано список продуктів і сторінку з параметрами продукту;
- створено базовий адаптивний інтерфейс;
- налаштовано pytest і Ruff та підготовлено документацію.

## Тиждень 2 — Основа плагінної системи

Заплановано:

- визначити мінімальний `Plugin API`;
- реалізувати `Plugin Manager`;
- додати локальне виявлення плагінів;
- створити перший плагін Executable Inspector;
- додати базове представлення результату перевірки executable;
- створити першу модель `Plugin Configuration` для окремого продукту;
- додати тести плагінної основи та Executable Inspector;
- підготувати матеріали для першої демонстрації.

### Фактичний результат Week 2

- створено `Plugin API`, `PluginManager` і built-in discovery;
- реалізовано Product-specific `PluginConfiguration`;
- додано Executable Inspector;
- реалізовано License Manager із Change Plan, backup, hide, restore, no-clobber і best-effort rollback;
- реалізовано Log Collector із bounded scan і ZIP-збиранням логів;
- покращено UI/UX сторінки Product;
- підготовлено 40 автоматичних тестів основного функціоналу;
- Snapshot comparison перенесено на наступний етап.

### Пріоритети наступного етапу

Історичний план наступних тижнів нижче збережено без змін. Log Collector уже реалізовано, тому повторно до актуальних пріоритетів не входить.

- Snapshot model;
- Snapshot Diff;
- базовий Windows Registry plugin;
- початкова Environment Profile.

## Тиждень 3 — Файлові операції та snapshots

Заплановано:

- створити плагін File Operations;
- додати базове представлення `Resource` для файлів та інших артефактів продукту;
- реалізувати резервне копіювання, тимчасове приховування та відновлення файлів;
- додати рівні ризику й явне підтвердження операцій;
- зберігати `Operation Logs`;
- додати базовий snapshot середовища продукту;
- реалізувати початкове порівняння snapshots;
- додати unit tests та integration tests.

### Фактичний результат Week 3

- реалізовано Snapshot Capture, Snapshot Diff, Snapshot Restore і керування
  Product-scoped snapshots;
- раніше історичного плану Week 4 реалізовано Windows Registry із values,
  branches, presets, preview, stale protection і підтверджуваним execution;
- раніше історичного плану Week 4 реалізовано Product-scoped Environment
  Profiles із Registry/License comparison та best-effort coordinated execution;
- збережено provider boundaries, one-time intents, PRG/F5 safety і redacted
  aggregate Operation Logs;
- після вузької раціоналізації suite збережено 191 автоматичний тест;
- Workflows не реалізовані й залишаються майбутнім етапом історичного плану.

## Тиждень 4 — Windows Registry та Environment Profile

Заплановано:

- виправити проблеми, знайдені під час перевірки, та врахувати відгуки, якщо вони будуть;
- створити плагін Windows Registry;
- залишити Windows-специфічну логіку поза ядром;
- додати базову модель `Environment Profile` / `Preset`;
- підготувати один простий profile для продукту без повного редактора profiles;
- ізолювати помилки плагінів;
- розширити автоматизовані тести;
- покращити вебінтерфейс і підготувати другу демонстрацію;
- написати чернетки вступу й огляду літератури для дипломної роботи.

## Тиждень 5 — Workflow, логи та Jira

Заплановано:

- додати базову модель `Workflow` / `Setup` і послідовність Plugin Actions;
- реалізувати один простий workflow без повного конструктора;
- створити базову версію Log Collector;
- додати мінімальну Jira Integration;
- підтримати передавання snapshot або зібраних артефактів до Jira issue;
- підготувати шаблон для розробників плагінів;
- написати чернетку розділу про методологію;
- почати розділ із результатами.

## Тиждень 6 — Feature freeze і стабілізація

Заплановано:

- завершити Log Collector і основні інтеграційні сценарії;
- не додавати нові функції після feature freeze;
- виправити помилки та стабілізувати роботу продуктів, profiles і workflows;
- перевірити інтегровану роботу snapshot diff;
- налаштувати CI;
- підготувати пакування застосунку;
- підготувати фінальну демонстрацію;
- завершити чернетку дипломної роботи.

## Тижні 7–8 — Реліз і захист

Заплановано:

- підготувати release candidate;
- виконати фінальну перевірку та внести потрібні виправлення;
- підготувати презентацію;
- підготуватися до захисту.

## Поза межами MVP

- повна sandbox-ізоляція недовірених плагінів;
- повноцінний візуальний конструктор для всіх profiles і workflows, якщо він не потрібен для основної демонстрації;
- функції, які не потрібні для тижневих цілей або фінальної демонстрації;
- широка підтримка інших платформ, якщо вона ускладнює поділ між кросплатформним ядром і Windows-специфічними плагінами.
